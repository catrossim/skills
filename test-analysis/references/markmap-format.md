# 思维导图格式约定（Markmap）

导图文件是主文档的**结构投影**，格式遵循 Markmap 语法（可在 https://markmap.js.org 或 VS Code "Markmap" 扩展中打开）。主文档是唯一权威源：修改先改主文档，再同步导图；两者条目数必须一致。

## 文件格式

文件名：`<功能名>.test-analysis.mindmap.md`，与主文档同目录。写入前检查同名文件，存在则加 `-2`、`-3` 后缀，禁止静默覆盖。

```markdown
---
title: <功能名> <版本> 测试功能点
markmap:
  colorFreezeLevel: 2
  maxWidth: 300
---

# <功能名> <版本>

## <模块/分支 1>
- FP-XXX-01 <行为短语>
- FP-XXX-02 <行为短语>

## <模块/分支 2>
- FP-XXX-03 <行为短语>
  - <可选：下级限定说明，短语化>
```

## 层级与节点规则

| 层级 | 对应内容 | 要求 |
|------|----------|------|
| `#`（唯一） | 被测功能名 + 版本 | 全文有且仅有一个一级标题 |
| `##` | 模块/主分支（对应主文档 §2.x 小节） | 数量与主文档小节一致，顺序一致 |
| `-` 列表 | 功能点 | 每条 = `FP-编号` + 行为短语 |
| 嵌套列表 | 限定说明（可选） | 最多一层，仅当必要 |

节点写作规则（借自 mindmap-skills 实践）：

- **短语化**：每个节点是简短标签（约 ≤8 词），不抄主文档整句；完整描述以编号回溯主文档为准
- **深度 3–4 层**：`#` → `##` → `-` 通常已够；出现第 5 层说明主文档模块切分有问题，回头改主文档
- **保留编号**：FP 编号是导图与主文档的唯一纽带，任何节点不得省略
- **待确认标记**：主文档中 ⚑ 的条目，导图节点加 `⚑` 后缀，如 `- FP-LOGIN-05 连续失败锁定 ⚑`
- 行内 markdown（`**加粗**`、`` `代码` ``）可用；不放表格、长句、链接清单

## frontmatter

固定沿用默认值 `colorFreezeLevel: 2`、`maxWidth: 300`，不要改动或删除 `---` 块——Markmap 依赖它渲染标题样式。

## 可选：渲染交互式 HTML

用户要求"渲染/出 HTML"时执行：

```bash
npx --yes markmap-cli "<导图.md 路径>" -o "<同目录同名>.html" --no-open
```

降级处理（任一情况都不算任务失败）：

- 无法执行命令 / 缺少 Node.js / npx 下载失败 → 保留 `.md`，说明未生成 HTML 的原因，并提供上面这条命令让用户在有 Node.js 的环境自行执行
- 渲染成功会在输出路径生成独立 HTML，浏览器直接打开即为交互导图

完成后告知用户两个产物的路径及导图查看方式（markmap.js.org / VS Code Markmap 扩展 / 生成的 HTML）。
