# 组织模式：功能分解型 / 维度展开型 / 混用

选模式的原则：**需求怎么写，主干就怎么切**。本章先给判别规则，再给两种模式的完整结构与示例。

## 模式判别

| 需求的特征 | 功能类型 | 采用模式 |
|------------|----------|----------|
| 按用户操作/流程描述（下单、审批、注册、CRUD） | 流程型 | 功能分解型 |
| 按规则/公式/算法描述（计费、折扣、排序、配额） | 计算型 | 维度展开型 |
| 主流程 + 内嵌计算规则 | 混合型 | 主干功能分解 + 计算子功能挂维度子图 |

混合型的典型做法：主干各分支用功能分解型；凡涉及金额计算、状态机、并发竞争的子功能，在其下单独展开一张维度子图（层级 ≤4 层，超了就只保留高风险维度）。

## 模式一：功能分解型

主干用产品/业务语言，分支与需求章节直接对应，叶子为功能点。

```text
<功能名> <版本>
├── <子功能 A>          ← 与需求章节对齐
│   ├── FP-XXX-01 <行为级条目>
│   └── FP-XXX-02 <行为级条目>
├── <子功能 B>
└── 非功能（仅需求明确规定的）
```

组织要求：

1. 一级分支 = 子功能/操作，命名用需求原文的术语，不自创名词
2. 逐条需求映射进分支后，检查"正常路径之外"的分支是否存在——流程型功能最常见的遗漏是只列了成功路径
3. 非功能分支只收需求明确规定的项（性能指标、安全要求）；未规定的丢弃，不杜撰

示例（优惠券，节选）：

```text
优惠券功能 v3.1
├── 领取优惠券
│   ├── FP-COUPON-01 活动页领取，每人限领 N 张（需求§5.2）
│   ├── FP-COUPON-02 库存为 0 时不可领取并提示（需求§5.3）
│   └── FP-COUPON-03 新用户专享券非新用户不可领（需求§5.4）
├── 下单使用
│   ├── FP-COUPON-07 提交订单后券状态 未使用→已锁定（需求§6.1）
│   └── [子图] 抵扣金额计算 → 维度展开
└── 退回与失效
    ├── FP-COUPON-11 订单取消未支付，锁定券自动退回（需求§6.4）
    └── FP-COUPON-12 过期时刻的在途订单处理（需求§6.6）
```

## 模式二：维度展开型

主干按测试对象的受力面展开。适用于计算型功能——这类功能的"行为"与"数据"不可分（不指定"订单额恰等于门槛"，就无法定义"自动选最优券"这个行为），因此维度分支里允许出现带具体数据形态的条目，仍标 `需求§` 或 `[推导]` 区分。

六个标准维度（按需裁剪）：

| 维度 | 收什么条目 |
|------|------------|
| 数据（输入域） | 关键输入的取值形态：极值、空、边界关系（<、=、>） |
| 规则组合 | 多规则叠加/互斥/优先级，组合后的结果定义 |
| 状态 | 实体的状态机：合法迁移、非法迁移、回退路径 |
| 时序与并发 | 竞态、乱序、重复触发、同时操作 |
| 精度与计算 | 舍入、误差累积、计算顺序 |
| 端与配置 | 多端一致性、配置组合、开关 |

示例（优惠券核销计算，节选）：

```text
[子图] 优惠券核销金额计算
├── 数据
│   ├── FP-CPN2-01 订单额恰等于门槛时，券可用且不重复优惠（需求§6.2）
│   └── FP-CPN2-02 抵扣后金额为 0 元，订单可提交为 0 元单 [推导]
├── 规则组合
│   ├── FP-CPN2-03 券与商品折扣同时生效，按需求§6.3 优先级扣减
│   └── FP-CPN2-04 多张可用券的"最优"判定与需求§6.4 一致
└── 时序与并发
    └── FP-CPN2-05 下单瞬间券过期，以服务端下单请求时间为准 [推导]
```

## 模式选择的常见错误

- 流程型功能错用维度展开：导致与需求对不上号，评审时产品无法逐条核对 → 流程型一律功能分解
- 计算型功能硬套功能分解：只列出"可计算""不可计算"两个分支，遗漏数据形态与组合 → 涉及规则的子功能必须维度化
- 维度子图层级失控：超过 4 层时砍低风险维度，保留数据、规则组合、时序并发三个维度即可
